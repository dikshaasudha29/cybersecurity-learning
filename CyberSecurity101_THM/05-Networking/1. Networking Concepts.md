# Task 2 – OSI Model

## Objective

Deconstruct the International Organization for Standardization (ISO) Open Systems Interconnection (OSI) 7-layer reference model from Layer 1 (Physical) through Layer 7 (Application).

## Key Concepts

- **OSI Model Hierarchy:** A theoretical framework defining end-to-end communication across 7 distinct layers.

- **Mnemonic:** "Please Do Not Throw Spinach Pizza Away" (Physical → Data Link → Network → Transport → Session → Presentation → Application).

### OSI Model Layer Breakdown

| Layer | Name | Description |
|-------|------|-------------|
| **Layer 1** | Physical Layer | Handles raw binary bit transmission over physical media (copper Ethernet wires, optical fiber cables, RF bands like 2.4 GHz / 5 GHz WiFi). |
| **Layer 2** | Data Link Layer | Manages node-to-node frame transfer within the same local network segment using hardware Media Access Control (MAC) addresses (6-byte hexadecimal identifiers). Protocols: Ethernet (802.3), WiFi (802.11). |
| **Layer 3** | Network Layer | Manages logical addressing, packet structure, and path selection (routing) across distinct networks. Protocols: IP, ICMP, IPSec. |
| **Layer 4** | Transport Layer | Controls end-to-end process communication, error detection, flow control, and data segmentation. Protocols: TCP, UDP. |
| **Layer 5** | Session Layer | Establishes, maintains, and synchronizes active communication sessions between distributed applications. Protocols: NFS, RPC. |
| **Layer 6** | Presentation Layer | Translates, formats, encodes, compresses, and encrypts data into a uniform structure usable by the application layer. Standards: ASCII, Unicode, MIME, JPEG, TLS/SSL. |
| **Layer 7** | Application Layer | Provides direct network interface access and protocols to user software applications. Protocols: HTTP, HTTPS, FTP, DNS, SMTP, POP3, IMAP. |

### OSI Reference Matrix

| Layer # | Layer Name | Key Function | Primary Identifiers / Standards |
|---------|------------|--------------|--------------------------------|
| Layer 7 | Application | Network service interface for user applications | HTTP, FTP, DNS, SMTP, POP3, IMAP |
| Layer 6 | Presentation | Data encoding, translation, encryption, compression | MIME, ASCII, Unicode, JPEG, PNG |
| Layer 5 | Session | Session state initialization, management, & sync | NFS, RPC |
| Layer 4 | Transport | Process-to-process communication, segmentation | TCP, UDP (Port Numbers) |
| Layer 3 | Network | Logical addressing and inter-network routing | IP, ICMP, IPSec (IP Addresses) |
| Layer 2 | Data Link | Segment-local node transfer & hardware framing | Ethernet (802.3), WiFi (802.11) (MAC) |
| Layer 1 | Physical | Raw bitstream transmission across physical media | Electrical signals, Fiber optics, RF |

## What I Learned

Layer 2 MAC addresses govern communication within a single local collision/broadcast domain, whereas Layer 3 IP addresses govern communication across router boundaries.

Industry terms like "Layer 3 Switch" or "Layer 7 Firewall" directly reflect the highest OSI layer at which the device or security engine inspects traffic.

# Task 3 – TCP/IP Model

## Objective

Analyze the practical, implemented TCP/IP architecture (RFC 1122) and map its consolidated layers to the 7-layer ISO OSI reference model.

## Key Concepts

- **Origin & Purpose:** Developed by the U.S. Department of Defense (DoD) to ensure continuous network survivability and dynamic re-routing during link failures.

### OSI vs. TCP/IP Layer Mapping

| OSI Model (7 Layers) | TCP/IP Model (4 Layers - RFC 1122) | Modern Internet Stack (5 Layers) |
|----------------------|-------------------------------------|----------------------------------|
| 7. Application | Application Layer | Application Layer |
| 6. Presentation | | |
| 5. Session | | |
| 4. Transport | Transport Layer | Transport Layer |
| 3. Network | Internet Layer | Network Layer |
| 2. Data Link | Link Layer | Link Layer |
| 1. Physical | (Included in Link Layer) | Physical Layer |

## What I Learned

The TCP/IP Application layer groups OSI Layers 5, 6, and 7 into a single implementation stack, leaving data encoding, formatting, and session management to the application binary itself.

# Task 4 – IP Addresses and Subnets

## Objective

Examine IPv4 addressing structures, octet math, network/broadcast reserved addresses, CIDR notation, private IP address ranges (RFC 1918), and Layer 3 packet routing logic.

## Key Concepts

- **IPv4 Architecture:** 32-bit logical address split into 4 octets (8 bits each, decimal range 0–255). Total address space $\approx 2^{32} \approx 4.29 \text{ billion}$.

### Reserved Subnet Addresses

- **Network Address:** First address in subnet (host bits all 0; e.g., 192.168.1.0). Identifies the network segment.
- **Broadcast Address:** Last address in subnet (host bits all 1; e.g., 192.168.1.255). Targets all hosts on the segment.

### Subnet Masks & CIDR

- `255.255.255.0` corresponds to `/24` (leftmost 24 bits are locked for the network ID; remaining 8 bits allow 254 usable host IPs).

### Private IP Address Ranges (RFC 1918)

| Class | Range |
|-------|-------|
| Class A | 10.0.0.0 – 10.255.255.255 (10.0.0.0/8) |
| Class B | 172.16.0.0 – 172.31.255.255 (172.16.0.0/12) |
| Class C | 192.168.0.0 – 192.168.255.255 (192.168.0.0/16) |

## Commands Used

```bash
# Linux: View active network adapter configurations and assigned IPv4/IPv6 addresses
ifconfig
ip a s

# Windows: Query network interface IP address, subnet mask, and default gateway
ipconfig /all
```

## What I Learned

Private IP addresses defined in RFC 1918 cannot be routed directly across the public Internet and require Network Address Translation (NAT) at the perimeter router.

Invalid IPv4 octet values (e.g., numbers exceeding 255 like 192.168.305.19) are illegal.

# Task 5 – UDP and TCP

## Objective

Compare the operational mechanisms, header overhead, and reliability guarantees of User Datagram Protocol (UDP) and Transmission Control Protocol (TCP) at Transport Layer 4.

## Key Concepts

### Port Numbers

- **16-bit process identifiers ranging from 1 to 65535 (Port 0 is reserved).**

### UDP (User Datagram Protocol)

- **Type:** Connectionless, lightweight, unacknowledged.
- **Characteristics:** No handshake, no sequence tracking, no retransmission mechanisms. Optimized for speed and low latency (e.g., DNS queries, video streaming).

### TCP (Transmission Control Protocol)

- **Type:** Connection-oriented, reliable, ordered stream.
- **Characteristics:** Employs sequence/acknowledgment numbers, flow control, and error recovery.

### TCP Three-Way Handshake

- **SYN:** Client selects a random initial sequence number ($SEQ_C$) and transmits a SYN packet to the server.
- **SYN-ACK:** Server acknowledges with ACK ($SEQ_C + 1$) and transmits its own random initial sequence number ($SEQ_S$) via a SYN-ACK packet.
- **ACK:** Client confirms reception by sending an ACK ($SEQ_S + 1$), establishing the bidirectional connection state.

```text
Client                               Server
  |                                     |
  | ------------ SYN (Seq=X) ---------> |
  |                                     |
  | <------- SYN-ACK (Seq=Y, Ack=X+1) - |
  |                                     |
  | ------------ ACK (Ack=Y+1) -------> |
  |                                     |
  [Connection Established - Data Begins]
```

## What I Learned

TCP guarantees data arrival and order via sequence numbers at the cost of latency overhead, whereas UDP trades guaranteed delivery for high-speed packet transmission.

Total available socket port numbers per IP address count to $2^{16} - 1 = 65,535$.

# Task 6 – Encapsulation

## Objective

Trace the data encapsulation sequence across the protocol stack as application data descends to physical transmission, and examine the lifecycle of a packet.

## Key Concepts

- **Data Encapsulation:** The process where each descending layer wraps the upper-layer payload with its own control header (and optional trailer) before handing it down.

### Protocol Data Units (PDUs)

```text
[ Application Data ]                        --> Application Layer Data
[ TCP/UDP Header ] [ Application Data ]     --> Transport Layer (Segment / Datagram)
[ IP Header ] [ Transport Header ] [ Data ] --> Network Layer (IP Packet)
[ Link Header ] [ IP Packet ] [ Trailer ]   --> Data Link Layer (Frame)
```

### Packet Lifecycle (Example: Navigating to a Web Page)

- **Application Layer:** Web browser formats an HTTP/HTTPS GET request payload.
- **Transport Layer:** TCP attaches source/destination ports and initiates the 3-Way Handshake to construct a TCP Segment.
- **Network Layer:** IP attaches source and destination IP addresses to wrap the segment into an IP Packet.
- **Link Layer:** Ethernet/WiFi attaches source/destination MAC addresses and a Frame Check Sequence (FCS) trailer to construct a Frame for physical transmission.
- **Intermediate Routing:** Routers strip Layer 2 link headers, evaluate Layer 3 IP headers to make forwarding decisions, append new Layer 2 headers for the next hop, and transmit downstream.
- **Decapsulation at Destination:** Target server receives frame, validates link trailer, strips Layer 2 → Layer 3 → Layer 4 headers, and delivers pure HTTP application payload to web server software.

## What I Learned

Encapsulation isolates protocol responsibilities: routers operate primarily on Layer 3 IP headers without needing to parse upper-layer TCP stream parameters or application HTTP payloads.

# Task 7 – Telnet

## Objective

Use the interactive telnet utility to manually establish raw TCP connections to target server socket ports (Echo on Port 7, Daytime on Port 13, HTTP on Port 80).

## Commands Used

```bash
# Connect to Echo Server (Port 7) - Echoes typed input strings back to terminal
telnet <MACHINE_IP> 7

# Escape Telnet prompt manually
# Press CTRL + ]
telnet> quit

# Connect to Daytime Server (Port 13) - Returns current remote server system time and closes
telnet <MACHINE_IP> 13

# Connect to Web Server (Port 80) and issue a manual HTTP/1.1 request
telnet <MACHINE_IP> 80
```

### Manual HTTP Interrogation Workflow

Once connected to Port 80 via telnet, manually issue the following request parameters followed by two **[ENTER]** keypresses (blank CRLF line):

```http
GET / HTTP/1.1
Host: telnet.thm
```


## What I Learned

telnet provides an unencrypted raw TCP terminal connection, making it an excellent lightweight diagnostic tool for auditing open ports, testing banners, and manually formatting application protocols (like HTTP).

Standard web server responses include diagnostic headers (e.g., `Server: Apache/2.4.41`) that disclose critical software names and version build numbers during banner grabbing assessments.

# Overall Takeaways

- **Abstracted Layering:** Network architectures depend on modular separation. Changes at the physical media layer (e.g., switching from Ethernet to WiFi) do not disrupt Layer 3 routing or Layer 7 HTTP processing.

- **Addressing Hierarchy:** Network routing requires a clear progression of identifiers: physical hardware locations (MAC) → logical network topology locations (IP) → specific process endpoints (Port).

- **Transport Selection Tradeoffs:** Security and system architects choose TCP when data integrity, ordering, and delivery guarantees are mandatory, and UDP when speed and overhead minimization take priority.
